# 部署指南

把小米小爱音箱的回答大脑换成你自己的大模型，**不刷机、不破坏小米智能家居**。

---

## 一、确认你的设备型号

本项目在 **Xiaomi Sound by HARMAN AudioEFX（型号 L16A）** 上完整验证过。
其他型号也能用，但需要自己确认硬件指令号。

### 查自己的设备信息

音箱和电脑连同一个 Wi-Fi，然后：

```bash
# 看局域网里的 mDNS 广播（TXT 记录里就有 model / manufacturer）
dns-sd -B _airplay._tcp local

# 看设备端口（小米音箱会开 8899）
nc -v <音箱IP> 8899
```

拿到 **IP** 和 **model** 后填进 `config.yaml`：

```yaml
hardware: "L16A"      # 你的型号
mi_did: ""            # 留空会按型号自动匹配
```

### 为什么不刷机

| 路线 | 原理 | 小米智能家居 | 代价 |
|---|---|---|---|
| **A. 不刷机**（本项目） | 保留小爱原生 ASR/TTS，只换「回答大脑」 | ✅ **100% 保留** | 唤醒词仍是「小爱同学」 |
| B. 刷机 | 接管麦克风音频和嘴巴 | ⚠️ 需自己接 Home Assistant | 可能变砖、失去保修、仅少数机型支持 |

L16A 在社区刷机方案的兼容表里标注为 "not tested"，同代固件还有 DER 证书签名校验，
**没有可用的刷机方案** —— 所以「不刷机」对这台设备不是妥协，是唯一稳妥的路。

## 二、装环境

```bash
git clone <本仓库地址>
cd <仓库目录>

uv venv --python 3.12 xiaogpt-env
VIRTUAL_ENV=$PWD/xiaogpt-env UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
  uv pip install "xiaogpt[locked]" miservice_fork
```

> ⚠️ **必须用 `xiaogpt[locked]`，不能用 `xiaogpt`。**
官方默认会装 langchain 1.4.x，而 `langchain.memory` 在 langchain 0.3+ 已被移除，
`import` 阶段就报 `ModuleNotFoundError: No module named 'langchain.memory'`，起不来。
locked 组把 langchain 锁在 0.3.27。

国内直连 PyPI 会超时，所以加了清华镜像。

### 装 PyInstaller（只有要打包桌面版才需要）

```bash
VIRTUAL_ENV=$PWD/xiaogpt-env UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
  uv pip install pyinstaller pywebview
```

## 三、配置

```bash
cp .env.example .env
chmod 600 .env
./xiaogpt-env/bin/python tools/setup_wizard.py
```

向导会依次：

1. 提示输入**小米ID**（米家 App → 我的 → 个人信息 → 小米ID，**不是手机号**）和密码（不回显）
2. 登录小米云、拉设备列表，**自动识别出你的音箱并打印它的 miotDID**
3. 生成 `config.yaml` 和 `.env`

### `.env` 里放什么

```bash
MINIMAX_API_KEY=你的key          # 大模型 + TTS 密钥
MI_USER=你的小米ID
MI_PASS=你的密码
MI_DID=音箱的miotDID              # 向导会自动填
MI_DEVICE_ID=固定deviceId        # 小米风控按设备，过一次验证码后这个设备能直接登录
```

> ⚠️ **key 不能跨区域用**：国内 key 只能打 `api.minimaxi.com`，
国际 key 只能打 `api.minimax.io`，混用会 401。

## 四、跑起来

```bash
./run.sh
```

### 怎么用

| 说的话 | 谁来响应 |
|---|---|
| 「小爱同学，**帮我**介绍一下量子计算」 | **你的 AI** |
| 「小爱同学，**请问**今天天气」 | **你的 AI** |
| 「小爱同学，开始持续对话」 | **你的 AI**（说「结束持续对话」退出） |
| 「小爱同学，打开客厅灯」 | 小爱原生（智能家居照常） |
| 「小爱同学，播放音乐」 | 小爱原生 |

### 自测（不用真人说话）

```bash
# ① 只测模型：问一句，看它回什么
./xiaogpt-env/bin/python tools/speaker_test.py --question "用一句话介绍量子计算" --no-tts

# ② 测音箱出声
./xiaogpt-env/bin/python tools/speaker_test.py --say "小智在这儿，链路正常"

# ③ 看输入侧：拉音箱对话记录，确认「你说的话」能被读到
./xiaogpt-env/bin/python tools/speaker_test.py --records

# ④ 控制台自检
./xiaogpt-env/bin/python -m console.selftest
```

## 五、控制台

### 浏览器版（局域网，手机也能用）

```bash
./console/run_server.sh start     # 启动
./console/run_server.sh status    # 状态
./console/run_server.sh stop      # 停止
./console/run_server.sh restart   # 重启
./console/run_server.sh log       # 看日志
```

启动后终端会打印带令牌的地址：

```
  http://<你的局域网IP>:8848/?token=xxxxxxxxxxxxxxxxxxxx
```

同一个 Wi-Fi 下用手机 / 别的电脑打开即可。
令牌存 `~/.xiaozhi/access_token`（600），换令牌删掉该文件重启即可。

### 桌面版（macOS .app）

```bash
./console/build_app.sh
```

产物 `dist/小智控制台.app`，已做 ad-hoc 签名，双击就能用。
配置和密钥落在 `~/.xiaozhi/`，**不会写进 App 包**。

## 六、MIoT 通道（麦克风静音 / 勿扰 / 唤醒 / 云端播报）

小米有**两套互不相通的云端会话**：

| 会话 | 端点 | token 字段 | 能干什么 |
|---|---|---|---|
| 小米云对话 / ubus | `api2.mina.mi.com` | `micoapi` | 音量、播放控制、TTS、对话记录 |
| **MIoT** | `api.io.mi.com` | `xiaomiio` | 麦克风静音、勿扰、云端播报、唤醒 |

**MIoT 必须单独过一次真人身份验证**（图形验证码 + 短信，自动化做不了）：

```bash
# ① 打印验证链接（浏览器打开）
./xiaogpt-env/bin/python tools/miot_login_probe.py

# ② 在浏览器里过验证（图形验证码 + 短信）后，拿到 file_id 写回 token
./xiaogpt-env/bin/python tools/miot_login_probe.py --save
```

拿到之后 `~/.mi.token` 里会多出 `xiaomiio` 字段。

### 常用 MIoT 操作

```bash
./xiaogpt-env/bin/python tools/miot_rw.py get 2 1            # 读音量
./xiaogpt-env/bin/python tools/miot_rw.py set 4 1 true       # 麦克风静音
./xiaogpt-env/bin/python tools/miot_rw.py set 9 1 false      # 勿扰关

./xiaogpt-env/bin/python tools/miot_rw.py action 7 1        # 唤醒音箱
./xiaogpt-env/bin/python tools/miot_rw.py action 7 3 '你好'  # 云端播报
```

> 这些工具需要 `MI_DID` 环境变量（你的音箱 miotDID）。

### 三个必须知道的坑

1. **prop/get 有会话内缓存** → 写完立刻读会拿到旧值，看起来像「没生效」。
   `miot_rw.py` 每次调用都是独立进程，就是为了绕开这个。
2. **code=0 不等于生效**。实测扬声器静音 (2,2)、休眠模式 (7,3)、循环模式 (3,3)
   云端都返回成功但设备忽略。写操作只在确认状态变化后才敢说生效。
3. **写入约 30 秒后才在云端可见**（设备属性上报有周期）。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: langchain.memory` | 装了 `xiaogpt` 而非 `xiaogpt[locked]` | 重装 `uv pip install "xiaogpt[locked]"` |
| `Login failed` / `Exception on login` | 账号密码错，或异地 IP 风控 | 核对小米ID；在本地网络重跑向导 |
| `we have no hardware: L16A` | 云端设备列表没匹配上 | 跑 `tools/list_devices.py` 看真实 hardware 字段 |
| `cannot find did for hardware` | MIoT 列表没匹配上 | 在 `config.yaml` 填 `mi_did`，或设 `MI_DID` |
| 终端有输出但音箱不播报 | 多为 TTS 通路问题 | 默认 `tts: mi` 走云端 ubus；确认硬件指令号 |
| AI 回「回答出错」 | key / base_url / 模型名不对 | 核对 `config.yaml` 的 `gpt_options.model` |
| 智能家居指令没反应 | 小爱账号本身未绑定设备 | 检查米家 App |
| `pip install` 卡住不动 | 直连 PyPI 超时 | 加 `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` |
| 音箱答两遍 | 跑着两个引擎 | 停掉多余的 |
| 手机打不开控制台 | 不在同一 Wi-Fi，或防火墙拦截 | 先在电脑本机 curl 局域网 IP 试试 |

## 八、安全约定

- **API key 只放 `.env`（600）**，绝不写进 `config.yaml`
- 小米 token 在 `~/.mi.token`（600），**只读不写** ——
  `miservice` 的 `login()` 失败时会把 token 文件**删掉**，那份 token 很贵

```bash
chmod 600 .env ~/.mi.token
```
