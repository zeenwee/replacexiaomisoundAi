# 浏览器版使用说明

把控制台跑在局域网里，手机、平板、别的电脑都能开。

---

## 一、启动

```bash
./console/run_server.sh start     # 启动（后台）
./console/run_server.sh status    # 看状态和访问地址
./console/run_server.sh restart   # 改完代码重启
./console/run_server.sh stop      # 停止
./console/run_server.sh log       # 看日志
```

启动后终端会打印带令牌的地址：

```
  http://<你的局域网IP>:8848/?token=xxxxxxxxxxxxxxxxxxxx
```

**在同一个 Wi-Fi 下，用手机 / 别的电脑打开其中一条就行。**
令牌会被浏览器记住（localStorage），以后直接访问 `http://<IP>:8848/` 也能进，
地址栏里的 `?token=...` 会被自动抹掉。

---

## 二、访问保护

| 模式 | 说明 |
|---|---|
| **默认（带令牌）** | 令牌存在 `~/.xiaozhi/access_token`（600），自动生成。接口一律校验令牌（`X-Token` 头 / cookie / `?token=`）。 |
| `--no-auth` | 完全不校验。**只在完全可信的网络里用**（比如自己一个人在家）。 |

```bash
# 换令牌：删掉文件重启服务，会重新生成
rm ~/.xiaozhi/access_token && ./console/run_server.sh restart

# 指定令牌
XIAOZHI_TOKEN=你的令牌 ./console/run_server.sh start

# 换端口
XIAOZHI_PORT=9000 ./console/run_server.sh start
```

**静态资源不设防，`/api/*` 全部校验令牌。**

---

## 三、和桌面版的关系

| | 桌面版 .app | 浏览器版 |
|---|---|---|
| 界面 | 同一套 `console/web/` | 同一套 `console/web/` |
| 后端 | `console/app.py`（pywebview 桥） | `console/server.py`（HTTP） |
| 启动 | 双击 .app | `./console/run_server.sh` |
| 配置位置 | `~/.xiaozhi/` | 项目目录 |

两边业务逻辑完全一致 —— 界面里改的触发词、音色、模型，和命令行跑的是同一套代码。

浏览器版多一层 `bridge-http.js` 垫片：把 `window.pywebview.api` 换成 `fetch` 请求，
所以同一份 `index.html` / `app.js` 两边都能用。

## 四、手机 / 折叠屏

界面按「合盖 / 展开竖 / 展开横」三档做了适配，断点不写死某一台机器的像素。

手机上：

- 侧边栏收成顶部标签栏，横向滚动
- 卡片改单列，表单控件加大到手指能点
- 「模拟触控热区」模式：给链接加 `?touch=1` 可以模拟触控设备

```bash
http://<你的局域网IP>:8848/?touch=1
```

## 五、HTTP 接口（想自己接的话）

所有接口走 `POST /api/call`，请求体 `{"name": "接口名", "payload": {...}}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/call` | 调用一个接口 |
| POST | `/api/task_status` | 查询慢操作的结果 |

```bash
TOKEN=$(cat ~/.xiaozhi/access_token)
curl -s -X POST http://127.0.0.1:8848/api/call \
  -H 'Content-Type: application/json' -H "X-Token: $TOKEN" \
  -d '{"name":"get_overview","payload":{}}'
```

慢操作（需要走网络的）会先返回 `{"immediate": false, "task_id": "..."}`，
拿 `task_id` 去 `/api/task_status` 轮询。

## 六、音色来源与响度（音色页）

音色页第一项是 **音色来源**，两个选项，改完自动重启引擎生效：

| 选项 | 底层配置 | 特点 |
|---|---|---|
| **MiniMax 音色** | `tts: minimax` | 音色可选（系统音色 + 克隆音色），能和小爱原生**区分开**；多约 0.5~0.8s 合成延迟 |
| **小爱原生音色** | `tts: mi` | 声音是音箱自己发的，**比 MiniMax 合成的声音大**、延迟几乎为零；代价是分不清哪句是 AI 答的 |

> **响度这件事要说清楚**：两条链路用的是**同一个音量通道**，响度差**纯粹来自源音频电平**。
小爱原生的母带更响；MiniMax 那一侧靠「响度」滑块补。
>
> 实测同一句话：`vol=1` RMS -24.0dBFS → `vol=4` **-12.1dBFS**（+11.9dB，0 削波）。
> 服务端会做归一化，**增益到 4 以后收益就饱和了**，再往上峰值顶到 0dBFS，听着是破音。
>
> 要**更响**优先去「设置」页调**音箱系统音量**（改喇叭输出增益，怎么调都不破音）。

### 克隆音色（音色页底部）

点「刷新」会问平台要这个账号下已有的克隆音色，可以直接「试听」「设为默认」。

> ⚠️ 用克隆音色必须把 **音色来源** 选成「MiniMax 音色」—— 选「小爱原生音色」
那条路不经过 MiniMax，克隆音色用不上。

克隆操作本身要上传音频文件，在项目目录跑命令行，步骤见
[音色克隆操作指南.md](音色克隆操作指南.md)。

## 七、MIoT 设备控制（设置页）

设置页有一张 **MIoT 设备控制** 卡，走的是小米的另一条云端通道（api.io.mi.com）：

| 按钮 | 作用 | MIoT 属性 |
|---|---|---|
| 读取状态 | 读回音量 / 静音 / 勿扰 / 分贝 | (2,1) (2,2) (4,1) (9,1) (10,2) |
| 麦克风静音 | 让音箱听不见唤醒词 | (4,1) |
| 勿扰 | 免打扰开关 | (9,1) |
| 唤醒音箱 | 远程唤醒 | action (7,1) |
| 云端播报 | 小米音色直接推一句话 | action (7,3) |

> **MIoT 需要单独过一次账号安全验证**。没有的话卡片会报错，
按 [部署指南.md](部署指南.md) 第六节补一次就行。

## 八、排障

| 现象 | 原因 / 办法 |
|---|---|
| 手机打不开 | 确认同一个 Wi-Fi；Mac 防火墙可能被拦（系统设置 → 网络 → 防火墙）；先在 Mac 上 curl 局域网 IP 试试 |
| 打开是「需要访问令牌」 | 链接后面少了 `?token=...`。在那台机器上 `cat ~/.xiaozhi/access_token` |
| 接口报「访问令牌无效」 | 浏览器 localStorage 里的旧令牌失效了，用新链接再打开一次 |
| 页面样式是旧的 | 静态资源已设 `Cache-Control: no-cache`，若仍异常就强刷（Cmd+Shift+R） |
| 改了代码没生效 | `./console/run_server.sh restart` |
| 端口被占 | `XIAOZHI_PORT=9000 ./console/run_server.sh start` |

## 九、开机自启（可选）

```bash
./console/launchd/install.sh            # 装 + 立刻启动
./console/launchd/install.sh --status   # 看状态
./console/launchd/install.sh --uninstall # 卸载
```

装完重启电脑生效。
